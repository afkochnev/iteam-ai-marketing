# ADR 002: модульный монолит и additive strangler

- Status: **Proposed**.
- Date: 2026-11-21.
- Scope: PR-A0, documentation-only.

## Context

В проекте уже есть FastAPI, Next.js, PostgreSQL и фоновые workers. Сейчас важнее определённые владельцы состояния и безопасная миграция, чем новые сетевые границы. Production должен продолжать работать, пока появляются CMS/email, новые assets и сквозное измерение.

## Decision

Сохранить модульный монолит. Каждый домен владеет своими прикладными командами и данными; связи проходят через контракты. API и изолированные AI/integration workers могут быть отдельными процессами, не становясь независимыми бизнес-системами с конкурирующей истиной. PostgreSQL — source of truth; Redis — транспорт.

Применять **additive strangler migration**: новые таблицы/контракты добавляются рядом; shadow reads и mapping проверяются до write cutover; на каждом scope действует один writer. Старый Publication write path отключается только после подтверждённого cutover. Legacy tables удаляются отдельным поздним release.

**Big-bang rewrite запрещён.** Действующий immutable release pipeline и эксплуатационные gates сохраняются. A0 не меняет код, Docker/Compose или схемы.

## Alternatives

- Микросервис на каждый домен: усложняет согласованность, наблюдение и операции до доказанной необходимости.
- Продолжение общего mutable слоя без владельцев данных: затрудняет контроль версий и безопасный cutover.
- Переписать приложение целиком: неприемлемое окно риска и потеря проверенной истории.

## Consequences

Модули требуют дисциплины зависимостей и контрактных тестов. Общая БД допускает атомарную фиксацию локальных решений/outbox, но не заменяет границы доступа. Извлечение отдельного сервиса допустимо позднее по доказанной нагрузке/изоляции, через новый ADR.

История не переписывается вручную. Rollback сохраняет новые таблицы и внешние факты; слепое восстановление старого backup и dual-write доставка запрещены. Открытые вопросы: Q1, Q10, Q11 в [roadmap](../architecture-v2/roadmap.md).
