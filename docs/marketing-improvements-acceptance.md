# Приёмка документа «Доработки отдела маркетинга»

Этап 2 откладывается до завершения пользовательских доработок.

| Требование | Реализация |
| --- | --- |
| Перенос запланированной публикации | Кнопка «Перенести», будущая дата, отдельный аудит; утверждённый план неизменен. |
| Отменённые после перепланирования | Старая запись сохраняется в истории; при новой запланированной или опубликованной записи не предлагается повторно в активном разделе отменённых. |
| Редактирование отменённого | Новая редакция с отдельным согласованием; повторное планирование создаёт новую запись. |
| Архивный материал | Создание копии с отдельным согласованием; оригинал сохраняется. |
| Возврат | Цепочки и обратные ссылки в разделах кампании, списках, карточках, формах создания и профиле. Обзор кампании возвращает в список кампаний. |
| Ошибки медиаплана | План и workspace обновляются после утверждения, предыдущие ошибки очищаются; создание поста без перезагрузки проверяется тестом. |
| Интервалы | Общие gap-правила для actions, отступы между кнопками и пояснениями, отдельные интервалы навигации и статуса сервиса. |
| Успех планирования | Дата, канал и утверждённая версия в сообщении; ошибки запроса отделены от успеха. Повторно планировать не требуется. |
| Состояние сервиса | Проверка ответа исполнителя по отдельной кнопке, без отправки постов, refresh или записи в БД. Флаг включения не считается доказательством готовности. При неполной проверке явно сообщается, что доступ к каналу и работа расписания не подтверждены. |
| Предупреждение о версии | Для неизменённой назначенной версии появляется при редактировании; реальное расхождение версий остаётся видимым. |
| Старые задачи медиаплана | Отдельная категория с датой/периодом и отменой через приложение. Четыре конкретные задачи ранее отменены через приложение; новый PR их не меняет. |
| Директор | После ошибок и блокировок — проверка назначенной публикации текущего плана. Старые материалы показаны отдельно, включая совпадение канала/времени. |
| Карточка старого поста | «Прежний медиаплан», пояснение до редакторских действий, ссылка на текущий план. Планирование старого слота не предлагается. Согласование текста не разрешает конфликт расписания. |
| Email администратора | Форма безопасной самостоятельной смены реализована в PR53. Применение afkochnev@gmail.com должен подтвердить владелец текущим паролем в профиле. Наличие формы не подтверждает фактическую смену. |

## Границы приёмки

- Успешный CI и готовый PR не означают, что изменения развёрнуты.
- Production, настройки VK/Telegram, токены и бизнес-состояния этот PR не меняет.
- Визуальная проверка проводится в отдельной среде с тестовой БД, без publishing credentials и исполнителей.
- Надпись «Готов к автоматической отправке» нельзя показывать без свежих подтверждений исполнителя, расписания и credentials. Пока API не имеет всех этих подтверждений, он сообщает об ограничении проверки.
